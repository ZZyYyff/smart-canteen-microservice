# K3S 部署方案说明

## 0. 环境要求

| 项目 | 最低要求 | 推荐 |
|------|----------|------|
| 操作系统 | Ubuntu 22.04+ / 24.04 | Ubuntu 24.04 |
| 内存 | 4 GB | 6 GB+ |
| 磁盘 | 20 GB | 30 GB+ |
| 容器运行时 | 已包含在 K3S 中 | — |
| Docker | 需要单独安装（用于构建镜像） | — |
| JDK | 17 | 17 |
| Maven | 3.8+ | 3.8+ |

## 1. K3S 安装

### 1.1 安装 K3S（单节点）

```bash
# 安装 K3S
curl -sfL https://get.k3s.io | sh -

# 验证
sudo k3s kubectl get nodes
```

### 1.2 配置 kubectl

```bash
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config
kubectl get nodes
```

### 1.3 Windows 宿主机远程控制 K3S

将 VM 的 `/etc/rancher/k3s/k3s.yaml` 复制到 Windows `C:\Users\<用户名>\.kube\config`，并修改 `server` 地址为 VM 的 IP。

如果 TLS 证书报错（自签名证书不含 VM IP），在 kubeconfig 中添加：

```yaml
clusters:
- cluster:
    insecure-skip-tls-verify: true
    server: https://<VM_IP>:6443
  name: default
```

## 2. 镜像加速（国内环境必备）

### 2.1 Docker 镜像加速

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://hub-mirror.c.163.com"
  ]
}
EOF
sudo systemctl restart docker
```

### 2.2 拉取基础镜像（走加速器）

基础镜像不能直接从 Docker Hub 拉，需通过加速域名：

```bash
# 拉取并打标签
docker pull docker.m.daocloud.io/library/eclipse-temurin:17-jre
docker tag docker.m.daocloud.io/library/eclipse-temurin:17-jre eclipse-temurin:17-jre

docker pull docker.m.daocloud.io/library/mysql:8.0
docker tag docker.m.daocloud.io/library/mysql:8.0 mysql:8.0

docker pull docker.m.daocloud.io/library/redis:7
docker tag docker.m.daocloud.io/library/redis:7 redis:7

docker pull docker.m.daocloud.io/nacos/nacos-server:v2.3.2
docker tag docker.m.daocloud.io/nacos/nacos-server:v2.3.2 nacos/nacos-server:v2.3.2
```

### 2.3 K3S containerd 镜像加速（可选）

如需让 K3S 直接拉镜像，编辑 `/var/lib/rancher/k3s/agent/etc/containerd/config.toml`：

```toml
[plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
  endpoint = ["https://docker.m.daocloud.io", "https://hub-mirror.c.163.com"]
```

然后 `sudo systemctl restart k3s`。

> 建议：自定义微服务镜像走 `docker save → k3s ctr images import` 方式，避免镜像加速器 403。

## 3. 源码前置修改

部署前需要确认以下源码配置正确，否则 Pod 会反复重启。

### 3.1 JDBC URL 必须使用环境变量占位符

`user-service/src/main/resources/application.yml`（同理 menu/order/pickup）：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3307}/smart_canteen?...
    username: ${MYSQL_USER:root}
    password: ${MYSQL_PASSWORD:root}
```

> 不要硬编码 `localhost:3307`，否则 K3S 中无法解析到 MySQL Service。

### 3.2 MySQL 镜像固定版本

`k8s/mysql.yaml` 中使用 `mysql:8.0` 而非 `mysql:8`：

```yaml
image: mysql:8.0
```

> `mysql:8` 可能指向 8.4+，该版本移除了 `mysql_native_password` 插件，导致 MySQL 无法启动。

### 3.3 自定义镜像必须设置 imagePullPolicy

所有自定义微服务的 Deployment 必须加：

```yaml
imagePullPolicy: IfNotPresent
```

> 默认 `:latest` 会触发 `Always` 拉取策略，但自定义镜像只存在于本地 containerd 中，远程仓库拉不到。

### 3.4 Nacos gRPC 兼容处理

Nacos 2.3.2 standalone 模式不启动 gRPC 端口 9848，需要让微服务使用 HTTP 注册：

```yaml
env:
  - name: SPRING_CLOUD_NACOS_DISCOVERY_EPHEMERAL
    value: "false"
```

### 3.5 JVM 内存控制

在微服务 Deployment 中添加 `JAVA_TOOL_OPTIONS`，避免 JVM 占用过多内存：

```yaml
env:
  - name: JAVA_TOOL_OPTIONS
    value: "-Xmx256m -Xms128m"
```

Nacos 也需要控制 JVM：

```yaml
env:
  - name: JVM_XMS
    value: "512m"
  - name: JVM_XMX
    value: "512m"
```

## 4. 构建 Docker 镜像

### 4.1 编译项目

```bash
cd ~/smart-canteen
mvn clean package -DskipTests
```

### 4.2 构建镜像

Dockerfile 的 context 必须在子模块目录：

```bash
cd user-service    && docker build -t smart-canteen/user-service:latest   . && cd ..
cd menu-service    && docker build -t smart-canteen/menu-service:latest    . && cd ..
cd order-service   && docker build -t smart-canteen/order-service:latest   . && cd ..
cd pickup-service  && docker build -t smart-canteen/pickup-service:latest  . && cd ..
cd gateway-service && docker build -t smart-canteen/gateway-service:latest . && cd ..
```

### 4.3 导入镜像到 K3S

**一次性导出导入**（磁盘空间充足时推荐）：

```bash
docker save -o ~/all-images.tar \
  mysql:8.0 redis:7 nacos/nacos-server:v2.3.2 \
  smart-canteen/user-service:latest \
  smart-canteen/menu-service:latest \
  smart-canteen/order-service:latest \
  smart-canteen/pickup-service:latest \
  smart-canteen/gateway-service:latest

sudo k3s ctr images import ~/all-images.tar
rm -f ~/all-images.tar
```

**逐个导入**（磁盘紧张时使用，拉一个→导一个→删 Docker 镜像→删 tar）：

```bash
docker pull docker.m.daocloud.io/library/mysql:8.0 && docker tag ... mysql:8.0
docker save mysql:8.0 -o /tmp/mysql.tar
sudo k3s ctr images import /tmp/mysql.tar
docker rmi mysql:8.0 && rm -f /tmp/mysql.tar
# ... 重复其他镜像
```

> 原因：Docker 和 K3S containerd 各存一份镜像，磁盘占用量翻倍。

### 4.4 验证导入

```bash
sudo k3s ctr images ls -q | grep -E "mysql|redis|nacos|smart-canteen"
```

预期输出 8 个镜像。

## 5. 部署服务

### 5.1 一键部署全部

```bash
cd k8s
kubectl apply -f namespace.yaml
kubectl apply -f configmap.yaml
kubectl apply -f mysql.yaml
kubectl apply -f redis.yaml
kubectl apply -f nacos.yaml
kubectl apply -f user-service.yaml
kubectl apply -f menu-service.yaml
kubectl apply -f order-service.yaml
kubectl apply -f pickup-service.yaml
kubectl apply -f gateway-service.yaml
```

### 5.2 等待就绪

```bash
# 基础设施
kubectl -n smart-canteen wait --for=condition=ready pod -l app=mysql --timeout=120s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=redis --timeout=60s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=nacos --timeout=300s

# 微服务（Nacos 就绪后再检查）
kubectl -n smart-canteen wait --for=condition=ready pod -l app=user-service --timeout=120s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=menu-service --timeout=120s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=order-service --timeout=120s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=pickup-service --timeout=120s
kubectl -n smart-canteen wait --for=condition=ready pod -l app=gateway-service --timeout=120s
```

### 5.3 验证部署

```bash
kubectl -n smart-canteen get pods -o wide
```

预期全部 `1/1 Running`：


## 7. 环境变量说明

| 环境变量 | 作用 | K3S 中的值 | 本地默认值 |
|----------|------|-----------|-----------|
| `MYSQL_HOST` | MySQL 主机地址 | `mysql` | `localhost` |
| `MYSQL_PORT` | MySQL 端口 | `3306` | `3307` |
| `MYSQL_USER` | MySQL 用户名 | `root` | `root` |
| `MYSQL_PASSWORD` | MySQL 密码 | `root` | `root` |
| `REDIS_HOST` | Redis 主机地址 | `redis` | `localhost` |
| `NACOS_SERVER_ADDR` | Nacos 地址 | `nacos:8848` | `localhost:8848` |

| `SPRING_CLOUD_NACOS_DISCOVERY_EPHEMERAL` | HTTP 注册模式 | `false` | — |

## 8. 常见问题排查

### 8.1 Pod Pending

```bash
kubectl describe node | grep -A5 Conditions
```

常见原因：

- **DiskPressure=True**：磁盘空间不足，清理日志和已驱逐的 Pod
- **MemoryPressure=True**：内存不足，增大 VM 内存或降低 JVM heap
- 镜像拉取失败：确认镜像已通过 `k3s ctr images import` 导入

### 8.2 Pod CrashLoopBackOff / Error

```bash
kubectl -n smart-canteen logs <pod-name> --tail=50
kubectl -n smart-canteen describe pod <pod-name> | grep "Exit Code"
```

常见退出码：

| 退出码 | 含义 | 排查方向 |
|--------|------|----------|
| 1 | 应用异常退出 | 查看日志 |
| 137 | OOMKilled | 增大内存或降低 JVM |
| 143 | SIGTERM（kubelet 主动终止） | 检查 liveness/readiness probe |
| 255 | JVM 无法启动 | JVM 参数过大、端口冲突 |

### 8.3 微服务无法注册到 Nacos

```bash
# 确认 Nacos 是否就绪
kubectl -n smart-canteen logs deployment/nacos --tail=5 | grep "started successfully"

# 确认服务是否注册成功
kubectl -n smart-canteen logs deployment/user-service | grep "register finished"

# 确认 ephemeral=false 已设置
kubectl -n smart-canteen exec deployment/user-service -- env | grep EPHEMERAL
```

关键错误对照：

| 错误日志 | 原因 | 解决 |
|----------|------|------|
| `port 9848 is available` | Nacos gRPC 未启动 | 添加 `EPHEMERAL=false` |
| `Connect timed out` / `Connection refused` | JDBC URL 用了 localhost | 改为 `${MYSQL_HOST}:${MYSQL_PORT}` |
| `ErrImagePull` / `ImagePullBackOff` | 镜像在远程仓库不存在 | 添加 `imagePullPolicy: IfNotPresent` |
| `mysql_native_password` unknown | MySQL 8.4 移除了该插件 | 固定 `mysql:8.0` |

### 8.4 磁盘压力（DiskPressure）

```bash
# 清理 systemd 日志
sudo journalctl --vacuum-size=100M

# 清理 apt 缓存
sudo apt clean && sudo apt autoremove --purge -y

# 清理 Docker 构建缓存
sudo docker system prune -a -f

# 清理 /tmp 和 /var/log 旧文件
sudo find /tmp -type f -mtime +7 -delete
sudo find /var/log -type f -name "*.gz" -delete
```

### 8.5 TLS 证书错误（Windows kubectl 连 VM K3S）

```
x509: cannot validate certificate because it doesn't contain any IP SANs
```

解决：在 `~/.kube/config` 的 cluster 配置中添加 `insecure-skip-tls-verify: true`，并删除 `certificate-authority-data`（二者互斥）。

### 8.6 清理与重新部署

```bash
kubectl delete namespace smart-canteen --timeout=120s

# 确认完全删除
kubectl get namespace smart-canteen 2>&1 | grep "NotFound"

# 重新部署
cd k8s
kubectl apply -f namespace.yaml && kubectl apply -f configmap.yaml
kubectl apply -f mysql.yaml && kubectl apply -f redis.yaml && kubectl apply -f nacos.yaml
kubectl apply -f user-service.yaml && kubectl apply -f menu-service.yaml
kubectl apply -f order-service.yaml && kubectl apply -f pickup-service.yaml
kubectl apply -f gateway-service.yaml
```
